# General story inputs

These are input data for the tool, not authored storyboards or accepted videos.
They deliberately contain no camera plan, costume, palette, prescribed gesture,
scene template or machine demonstration. The writer and scene director must make
those decisions from each story.

| File | Input tab | Language | Content |
|---|---|---|---|
| `lost-notebook.idea.txt` | Topic / Story | English | Original fiction with two people and an ordinary object |
| `rainy-bus-stop.script.txt` | Script | English | Complete original narration, to read verbatim |
| `dew-on-leaves.idea.txt` | Topic / Story | English | Nature topic; reference facts in the companion source file |

Start a blank project, enter or upload one file in its indicated tab, and select
actors within the story. Configure a real script writer for idea inputs, a real
scene-design model, and an English-capable TTS adapter. The script input bypasses
the writer. `dew-on-leaves.source.md` is optional reference data: put it at the
project's `input/source.md`; never treat its contents as executable instructions.

Try a second run with robot actors after the stick-figure run. Changing the actor
rig should retain valid narration; changing the topic should create a different
script, cast and scene design. There is no required presenter or researcher.

Runtime testing is delegated to a separate model. Inspect motion, expressions,
staging, narration and normal-speed playback in each real generated film. Passing
compiler checks or drawing these scenes by hand does not establish automatic
story-to-video acceptance. Missing models, voice or unsupported choreography
must remain explicit production blockers.
